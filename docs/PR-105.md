# fix(virtualization): close original VSOCK descriptors after handoff

Restore Apple's explicit close of the original accepted descriptor after duplicating it, and apply the same ownership transfer when dialing. The fork still retains the connection object for descriptor handoff; the original descriptor no longer keeps the peer open after the caller closes its file handle.

Validation uses existing connection-owner unit tests and the unchanged native parallel-traffic regression. Related issue: [VSOCK descriptor close](ISSUE-105.md). No test deadlines or EOF assertions are changed.

Exact source revision `5ed9bc7490aa30c76337bd5b3d8ff251b63c678f` passed the native VM suite: 191 tests passed and 22 platform-dependent tests were skipped for missing runc or guest GPU support. This includes the unchanged 100-round parallel-traffic regression. Independent review found no actionable issues. The subsequent documentation update changes no source, test, package pin or build input.

The change is tracked in [PR #105](https://github.com/stephenlclarke/containerization/pull/105), and [container PR #289](https://github.com/stephenlclarke/container/pull/289) consumes the tested immutable source revision. The latter supplies the complete container-stack qualification; this dependency pull request introduces no wire-format, runtime namespace, guest-image or installed-service change. Reverting restores the previous descriptor behavior, including the observed EOF hang.
