# fix(runtime): preserve VSOCK ownership and sync upstream runc fixes

The fork retains the Virtualization connection object during VSOCK descriptor handoff. Closing the original accepted or dialed descriptor after duplication lets the peer observe EOF when the caller closes its returned handle. The unchanged 100-round native parallel-traffic test covers that ownership behavior. Related issue: [VSOCK descriptor close](ISSUE-105.md).

This branch also incorporates Apple's `1fca8c5` runc launch fixes: `net.*` sysctls are applied in the guest's shared network namespace before runc receives the remaining OCI spec, and signalling an already-exited runc container succeeds without invoking `runc kill`. The upstream integration cases cover pod sysctl and exited-container behavior. This change adds focused guest behavior tests and an instrumented Linux coverage path for those branches. The SonarQube workflow combines actual Linux and macOS line hits only when both reports match the same commit, tree, and dependency lock; its existing source scope, policy, and quality gate remain unchanged.

The sysctl follow-up derives the guest's proc root from the existing cgroup proc-root URL and appends each component of a valid dotted sysctl key as a path component. Empty components and embedded slashes are rejected before any write, so a malformed key cannot alias a valid proc node. The existing sorted write order, raw `open`/`write`, and OCI-spec mutation only after successful writes are preserved. A Linux test drives the real container initializer through a unique nonexistent network sysctl and checks that it fails before bundle creation; a temporary-file test checks that malformed aliases cannot change a valid sysctl file.

The VSOCK-only revision `5ed9bc7490aa30c76337bd5b3d8ff251b63c678f` passed 191 native VM tests, with 22 platform-dependent skips for missing runc or guest GPU support. The upstream merge revision `ae9cdd597171181fa7f63053d4d56b28adaabd8e` passed the hosted Linux unit job (1,005 tests) and focused native checks. At `33a0122d81d574889e949c9eaa2b627cb35f6bb4`, five focused runc VM cases passed and the hosted instrumented Linux test and coverage-merge jobs passed, but Sonar's new-code coverage gate failed at 77.4% and three new hard-coded-path issues remained. The sysctl follow-up above addresses those findings; Swift formatting, syntax parsing, and diff checks pass locally. Linux package tests, a fresh Sonar scan, and final full VM validation of the follow-up are pending.

The change remains in [PR #105](https://github.com/stephenlclarke/containerization/pull/105). Its downstream consumer, [container PR #289](https://github.com/stephenlclarke/container/pull/289), requires its own source-matched qualification before release. No test deadline or EOF assertion is changed here.
