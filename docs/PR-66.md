# Pull request 66: serialize NBD persistence integration coverage

## Change

Pull request
[#66](https://github.com/stephenlclarke/containerization/pull/66) routes the
two-VM, write-heavy `cctl block NBD format and persist` case through the
integration suite's existing exclusive-execution lane. All other cctl block
and integration checks retain their concurrent scheduling.

## Motivation and context

Apple pull request
[#903](https://github.com/apple/containerization/pull/903) introduced the
coverage. The affected case passes alone but fails reproducibly alongside the
other new cctl block cases after successfully formatting the NBD export and
reading its UUID; Virtualization.framework then stops the VM unexpectedly
during teardown.

Related issue:
[#65](https://github.com/stephenlclarke/containerization/issues/65).

## Validation

- Before the change, the full suite passes 181/184, skips two, and fails this
  case.
- Before the change, the four cctl block cases pass 3/4 and fail this case.
- The affected case passes 1/1 in isolation in 2.98 seconds.
- After the change, the cctl block group passes 4/4 in 5.09 seconds.
- After the change, the full suite passes 182/184 with two expected skips in
  41.55 seconds.
- Swift formatting, Markdown lint, and diff checks pass; the Swift formatter
  reports only five pre-existing warnings outside this change.

## Compatibility and risk

Production behavior is unchanged. The test still proves that a filesystem
created inside one cctl VM is visible from a fresh second VM against the same
NBD export. Only its overlap with unrelated concurrent VZ-backed cctl
processes is removed.

## Upstream handoff

After the fork pull request receives exact-head review and required checks,
the same minimal scheduling correction and before/after evidence can be
offered to Apple against the originating pull request.
