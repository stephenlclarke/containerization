# Pull request 98: make Containerization SonarQube authoritative

## Summary

- Export the instrumented Swift package suite as project-confined LCOV and SonarQube generic coverage XML.
- Verify the project-level previous-version policy, label analyses with the exact checked-out commit, and wait for the quality gate.
- Reject unresolved new issues and unreviewed security hotspots on trusted pull requests, and reject every unresolved issue or unreviewed hotspot on `main`; fork and Dependabot pull requests skip the token-dependent job because repository secrets are unavailable to them.
- Upload manually dispatched short-branch analyses as diagnostic evidence without using SonarQube Cloud APIs that are unavailable for persistent short branches on the current plan.
- Keep generated integration fixtures in the test domain and exclude vendored libarchive headers from first-party metrics.

See [issue 97](https://github.com/stephenlclarke/containerization/issues/97) and its [repository handoff](ISSUE-97.md).

The authoritative hosted workflow supplied the Xcode 26.6 build, test, and
coverage evidence before merge. Main analysis
`ff29520703f083022397c2662a32a640b11420b7` then confirmed the exact revision,

a static project version necessarily initialized the previous-version
baseline, so its all-source new-code coverage is transitional rather than a
candidate comparison. This metadata-only closure gives the next scan a real
commit baseline without excluding maintained source.

## Compatibility and risk

Runtime behavior is unchanged. The source/test classification affects analysis only, and exclusions are restricted to generated Swift, generated integration fixtures, and the two named vendored libarchive headers. The maintained `archive_bridge.h` wrapper remains analyzed.

## Existing-code baseline

The first authoritative scan found 1,096 pre-existing maintainability findings.
Source classification removes 421 findings belonging to integration fixtures or
the vendored libarchive header. The remaining 675 are accepted individually in
SonarQube with the `apple-upstream-baseline` tag. This does not add a maintained
source exclusion or disable any rule: a new occurrence in any file remains
visible and blocks the pull-request or main gate. The accepted history remains
queryable for incremental upstream-compatible cleanup.
