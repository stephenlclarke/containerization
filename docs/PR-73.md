# Pull request 73: serialize VM-backed cctl run integration coverage

## Change

Pull request
[#73](https://github.com/stephenlclarke/containerization/pull/73) routes the
five subprocess-backed `cctl run` cases through the integration suite's
existing exclusive Virtualization.framework lane. The production
command-resolution implementation and all assertions remain unchanged.

## Motivation and context

Apple pull request
[#906](https://github.com/apple/containerization/pull/906) introduced the
coverage. The 0.14.2 release gate then exposed a concurrency-dependent teardown
failure: commands emitted their expected result, but overlapping cctl-owned VMs
could subsequently stop with `VZErrorDomain Code=1`.

Fork issue
[#69](https://github.com/stephenlclarke/containerization/issues/69) and pull
request [#70](https://github.com/stephenlclarke/containerization/pull/70)
established the same scheduling boundary for VM-backed `cctl --block` cases.

Related issue:
[#72](https://github.com/stephenlclarke/containerization/issues/72).

## Validation

- The full pre-change release suite passed 187/190 cases and skipped two; the
  remaining case failed after printing the expected `/bin/sh` output.
- The focused five-case group passed 3/5 with maximum concurrency four before
  the change and 5/5 with maximum concurrency one.
- The individually filtered failing case passed 1/1 under a maximum concurrency
  of four, isolating the failure to overlapping VMs rather than command
  resolution.
- At the pull request head, the focused five-case group passes 5/5 when the
  harness is invoked with maximum concurrency four.
- Swift formatting, signature verification, and diff checks pass.

## Compatibility and risk

Production behavior is unchanged. The only trade-off is roughly three seconds
of intentional serialization in the macOS integration suite, replacing a
host-level VZ scheduling failure with deterministic command-resolution
coverage.

## Upstream handoff

After exact-head review and required checks, the same minimal scheduling
correction and before/after evidence can be offered to Apple as a follow-up to
pull request #906. It should reference the related `cctl --block` scheduling
correction so reviewers can see the common Virtualization.framework boundary.
