# Fix split SwiftPM bundle coverage generation

## Motivation

Resolve #101. Current SwiftPM versions emit separate `.xctest` products,
while the inherited Makefile passes a removed aggregate executable to
`llvm-cov`. This blocks authoritative Sonar evidence and unattended
Container-family releases.

## Implementation

- Add a deterministic coverage-report helper that validates every test bundle
  executable and passes all of them to `llvm-cov`.
- Support Darwin bundle executables and the historical direct executable layout.
- Write reports through a temporary file so failed exports preserve the last
  complete report.
- Run focused helper regressions as a prerequisite of the coverage target.
- Document the supported SwiftPM layouts in the README.

## Validation

- `make coverage-tools-test`
- `make coverage-sonar`
- Markdown lint for the changed documentation

## Compatibility

There is no runtime or API change. The coverage command remains Xcode-backed
on macOS and accepts both old aggregate and new per-target SwiftPM layouts.

## Parity and performance

Docker and Docker Compose runtime parity are unaffected. The helper adds only
a fast local unit-test preflight and one `--object` argument per test target
to the existing coverage export.

## Risks

Future SwiftPM layouts that are neither standard Darwin bundles nor direct
`.xctest` executables will fail closed with an actionable diagnostic rather
than emitting incomplete coverage.
