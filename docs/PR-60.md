# Restore VZ pod lifecycle release contracts

## Pull request

<https://github.com/stephenlclarke/containerization/pull/60>

## Summary

- Retain a Linux pidfd for each managed process so signaling remains race-free
  across `wait4` reaping, and treat `ESRCH` or an already-published exit as an
  idempotent no-op.
- Accept loop-backed root filesystems below the bounded
  `/run/runtime-virtiofs-NN` device pool used by VZ runtime shares only when
  the corresponding reserved virtiofs mount is active.
- Resolve backing files relative to the verified mount with `openat2`,
  rejecting traversal, symlinks, mount crossings, malformed device tags,
  prefix siblings, and unrelated guest paths.
- Correlate the opened root descriptor's Linux mount ID with the exact
  virtiofs mount-table entry so stacked or concurrently replaced mounts cannot
  satisfy the trust check.
- Cover both contracts with focused Linux unit regressions.

## Motivation and context

The Containerization 0.14.0 release gate passed 175 of 180 integration
contracts and skipped two, but failed three VZ pod contracts. Repeated stop
and NBD cleanup attempted to resolve a PID after normal exit cleanup had
cleared it. Runtime block-rootfs hotplug produced a trusted
`runtime-virtiofs-NN` path that the guest validator did not yet recognize.

Issue: <https://github.com/stephenlclarke/containerization/issues/59>.

## Focused validation

- Swift formatting and diff checks passed.
- The guest executables built with the matching Swift 6.3 toolchain and Swift
  6.3 static Linux SDK with warnings as errors.
- The descriptor-only Linux open flag is supplied through the C shim so both
  glibc CI and the static-musl guest compile the same path.
- Focused Linux regressions cover published-exit signaling, required
  live-process descriptors, the reserved runtime tag boundary, active mount
  identity, ordinary nested file resolution, and intermediate symlink
  rejection.
- A rebuilt `vminit:latest` image passed the three formerly failing signed VZ
  integration contracts together: `pod stop container idempotency`,
  `pod NBD volume persistence`, and `pod hotplug block rootfs` (3/3 in 2.12
  seconds).

## Compatibility and risk

Running processes require the pidfd opened while the child is held behind its
startup handshake. The descriptor is closed on startup failure and
process-exit publication. The new path allowance is limited to the stable
unified mount and the 64 two-digit runtime device tags generated by the VZ
provider; active mount identity, regular-file, descriptor-relative
mount-ID correlation, no-symlink, and no-cross-mount checks remain in force
before a loop device can be attached. Cloud Hypervisor and boot-time mount
behavior are unchanged.
