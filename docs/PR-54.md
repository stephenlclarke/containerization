# Pull request 54: synchronize Apple main for 0.14.0

## Summary

- Merge Apple Containerization main through `4294c0f`.
- Import external-journal efsck recovery from Apple pull request 856.
- Import IPC namespace entry for exec from Apple pull request 851 while
  retaining the fork's complete namespace mask.
- Pin the reviewed SwiftNIO SSL support fork used by the matched 0.14.0 release
  graph.
- Repair links to the reorganized Compose documentation.

Pull request:
[#54](https://github.com/stephenlclarke/containerization/pull/54). Tracking
issue: [#53](https://github.com/stephenlclarke/containerization/issues/53).

## Implementation details

The only source merge conflict was the exec namespace mask. The resolution
retains USER, CGROUP, IPC, NET, PID, UTS, and NS entry plus the existing
conditional user-namespace guard. The package manifest selects SwiftNIO SSL
revision `09c5c9adcdd2a459187e45fe0143eb01063f244a`, matching Container and
Compose rather than allowing a standalone graph to resolve the unfixed Apple
release.

## Validation

- `ContainerizationEXT4Tests`: 66 tests passed.
- `LinuxNamespaceEntryTests`: 2 tests passed.
- `ContainerizationExtras` focused build passed against the reviewed TLS revision.
- Root and `vminitd` package resolution select the exact support-fork revision;
  both committed lockfiles pass resolution with automatic updates disabled.
- Hawkeye formatting and `git diff --check` are clean.
- Exact-head hosted tests, CodeQL, and connector review are required before merge.

SwiftPM reports its existing fork-override warning because upstream transitive
packages still declare the Apple SwiftNIO SSL URL. The resolved graph
nevertheless contains one package identity at the exact reviewed fork
revision. Removing that ecosystem-level warning would require coordinated
upstream dependency or mirror changes and is not hidden by this release.

## Compatibility and risk

The Apple source changes retain upstream ancestry and behavior. The TLS
dependency changes only the source and exact revision behind the existing
`swift-nio-ssl` package identity. Public Containerization APIs are unchanged.
The matched release root already uses the same revision.
