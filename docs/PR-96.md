# PR 96: publish exact fork VM-init images

Validated pushes to `stephenlclarke/containerization` main now publish the
already-tested `vminit:latest` image under the full source commit. Pull requests,
branches, and mutable aliases cannot enter this publication path.

The image carries the current repository as its OCI source, so GitHub links it
to the public fork before first publication. The package workflow no longer
runs directly on unprotected release-branch pushes. Pull-request builds use the
protected base workflow, remain package-read-only, and receive no registry
credentials. Only a separate job restricted to the trusted fork main or an
Apple release receives package-write authority.

Fork-main publication runs do not cancel an earlier main run when another
commit arrives, and each source SHA receives a distinct concurrency group.
Every accepted revision therefore reaches its exact-tag publication gate even
when multiple newer pushes are already queued.

Both registry-test helpers treat empty username or token values as absent, so
uncredentialed pull-request and non-main validation cannot accidentally send
an empty Basic authorization header.

The personal-account GHCR package was bootstrapped from the tested guest image
at exact source tag `a72855928c80986c732218b53325ad238f6d0efa` and made public
before this workflow became authoritative. Every fork-main publisher resolves
that tag anonymously before attempting a new push. This enforces the one-time
GitHub package visibility invariant using the same credential-free path as a
clean installation; a missing or private package fails before publication.
Token acquisition and manifest checks use bounded retries and per-request
timeouts so a transient registry failure does not defeat unattended runs.

Before pushing a source-commit tag, that job compares any existing remote
digest with the locally tested image and refuses replacement. It then obtains
an anonymous pull token and resolves the exact remote OCI manifest and digest.
A private, mutable, or otherwise credential-dependent image therefore fails
the bounded publication gate. Apple upstream release behavior is unchanged.
